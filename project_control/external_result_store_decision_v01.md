# 独立结果库与磁盘余量保护

用户明确批准在E:\Temp-Projects\PRL-results新建后续结果库，不搬移或删除旧结果。
本决定只取代新结果的固定256/800 MiB输出限额和“必须在代码仓内部输出”约束；
不改变历史合同、科学阶段授权、首失败停止、时限、单任务、GPU审批或删除审批。

代码仓保留源码、合同、状态投影和小型哈希索引；外部库保留新阶段输入副本、配置、
完整原始状态、日志、验证、Notebook及图件。只维护一套FEniCSx/Python实现，不复制内核。
既有results本已被Git忽略；它们不移动，旧链接保持，不以迁移为由开新版本重跑。
外部库不git init，也不上传GitHub；代码仓普通提交不可能包含其原始数组。

新结果准入按“可用磁盘>=本任务预计新增量+停止保全空间+10 GiB磁盘安全余量”。
不再设置固定单阶段体积上限；预测是资源规划，不是要求逐次申请容量额度。
停止保全至少64 MiB；未来模型状态更大时按最大完整状态提高。运行中持续检查余量，
将触底则停并保全，不自动清理旧证据。代码仓仍3 GiB硬限，外部结果单独统计，不计入该限额。

唯一配置是project_control/result_storage_policy.json；路径解析及磁盘门在src/prl/result_store.py。
当前前向FEniCSx轮廓运行器接入；旧退役路线及已完成阶段保留原限额/行为，不批量改写。
历史读取明确使用旧路径；新写入只进入外部库；同一ID在任一路径已存在就拒绝新建。
路径必须位于批准根内，无reparse point/符号链接，不允许通过盘符映射绕路。

验收包括路径越界拒绝、已完成阶段防重跑、无固定容量门、磁盘余量拒绝、旧数据哈希，
以及一次固定本地镜像的纯文件I/O容器测试；0FEM求解、0安装/拉取/网络/GPU。
容器主代码只读挂载，只有本次外部测试子目录可写。旧科学结果保持全部不变。

后续新增科学合同仍单独批准；当前局部J失败不会因移出结果而变成passed。
未来验证/绘图以显式结果根读取，不依赖结果目录倒推代码仓。代码仓索引记录阶段ID、
根内相对路径和清单SHA；外部路径更换或旧结果迁移仍须另行确认并验收。
