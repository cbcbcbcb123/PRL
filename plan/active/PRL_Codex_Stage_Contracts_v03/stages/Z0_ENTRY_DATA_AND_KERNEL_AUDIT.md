生产路线始终是：**唯一 `muse_dcm` 内核 + 主动心肌 DCM + 被动心内膜 DCM + 薄层 ECM 网络 + 自建最小 CFD**。本阶段未使用的模块保持关闭。不得复制第二套 DCM、用规定壁运动冒充主动双向耦合、用目标细胞体积缩小冒充收缩，或用合成分区冒充实验细胞膜。

同时阅读 `../01_GLOBAL_EXECUTION_CONTRACT.md`、`../02_VISUALIZATION_AND_DATA_CONTRACT.md` 和 `../03_VALIDATION_METRICS.md`。本文件已保留关键规则，脱离总包时也不得省略：只执行本阶段；保护用户修改与失败包；默认 CPU；阈值先冻结；结果与检查点分开；未运行字段为缺失而非零；失败也交付可视化；不因动画好看判 PASS。共享文件若缺失且影响公式、符号或验收，标记 `BLOCKED_SPEC`，不要猜。

## 1. 问题与允许范围

从一个入口看清：模型对象代表什么、代码从哪里来、哪些资料实际可读、哪些能力有运行证据。Z0 只做资料/源码审计、静态几何和 Z1 合同；不做主动收缩、动态组织、CFD 或泵血，不申请受限数据、不发送邮件、不下载巨大原始包。

完成不只意味着“有一个网页”，还意味着模型、资料、依赖路径和缺项表相互对应。`synthetic_entry_status` 与 `experimental_data_status` 分开；数据缺失不自动阻断合成入口。

## 2. Z0.1 定位项目、保留现场

记录实际路径、操作系统/CPU/内存、实际存在的编译环境、git 分支/提交和未提交修改，列出准备新增/修改的路径。历史 E 盘路径只是线索。定位唯一 `muse_dcm`，核验真实 import/构建路径，发现重复副本先说明，不删除、不复制。

读取现有 M1 记录和当前实际依赖测试；只有实际读过才能写“已核查”。每条能力列为 `available_and_tested / available_unverified / missing / failed / not_used`。对 FAIL 追到具体函数与本阶段依赖；门户上的 PASS/FAIL 数量不替代证据。

## 3. Z0.2 小文件与数据结构核查

按 [R1] Glasgow、[R2] 作者仓库、[R8] Zenodo 备用顺序检查，保存来源、许可、版本、文件大小和限制。官方影像与仓库速度是两个来源，不能默认已经配准。

在累计 256 MiB 下载上限内优先取两个相位小影像和一个速度快照；先看清单，禁止整包克隆大数据。实际文件记录 SHA-256、获取时间、格式与解析日志。不要直接运行下载代码；风险反序列化格式须先审计，优先安全读取或隔离转换。

检查鱼 ID、年龄 hpf、条件/温度、荧光标记、体素尺寸、轴顺序/左右手性、相位/时间定义、速度单位、不确定度和有效掩码。缺项即 UNKNOWN，文件名的 phase 数字不是自动确认的物理时间。

速度快照输出各数组 shape/dtype/数值范围/缺失比例，检查位置、速度与不确定度长度匹配。配准变换保存 R、t、尺度与轴置换；速度向量不能加空间平移。单位/配准未确认时仅并排展示，不能强行叠加或标为真实细胞尺度速度。

## 4. Z0.3 静态合成模型

使用已有几何生成器或独立前处理，不新建力学引擎。至少构建单闭合细胞、双闭合细胞、每层 4×4 个细胞的双层片。入口每细胞可选约 80–320 个面，但记录实际值；这不是正式收敛档位。

几何尺度可无量纲 L0，不冒充实验尺寸。可铺砌闭合多面体或已有适用几何均可，但相互穿透的球壳不是完整液密组织。每个细胞有腔面/基底面/侧面和层身份；双层标“心肌候选层/心内膜候选层，尚无动力学”。ECM 只显示候选连接/锚点，`geometry_only`，不输出假反力。

区分细胞闭合面、组织连接与未来共同腔面。组织片有真实边缘，不标完整心室。重复的两细胞皮质是否有不同物理归属说明清楚；不得在显示中填缝后声称已液密。

## 5. Z0.4 几何检查与语义表

检查索引有效、每个闭合细胞边的相邻面数、法向一致、正体积、自交、退化面、重复面、ID 与面归属。输出面积/体积/网格质量分布及错误位置。用一个可计算几何与独立体积公式交叉检查。

建立力学项表：每项的公式/源码位置、参考构型、单位、参数来源、材料方向、目标体积和阻尼物理对象。尚未实现的主动/ECM/CFD 路径标 planned，不能写“有 DCM 所以心肌可用”。

为 Z1 明确三档网格、时间步、加载路径、参考尺度、独立验证器、预算和失败条件；缺必要能力给最小修复任务与回归范围，不启动 Z1 正式计算。

## 通用执行闭环与最终答复

1. 保存工作区和依赖快照，记录已有未提交修改；不得覆盖、回滚、清理用户原始文件。
2. 在阶段专用目录保存 `preregistration.json`：方程、参数来源、单位、实验列表、非零参考尺度、阈值、随机种子、预算、代码/内核版本。正式结果产生后不得回调阈值。
3. 先做小规模预检并输出真实可检查的几何/字段；未经预检不得直接启动全量。预检失败就停在本阶段，不使用假数据填满页面。
4. 正式计算、可视化导出、独立验证分开；验证器从原始文件重算关键指标，不能仅相信求解器输出的 `passed=true`。
5. 交付 `report.md`、`summary.json`、`metrics.csv`、参数、真实执行命令、日志、原始快照、离线 `index.html`；适用时另交付可重启检查点。文件组织可适配现有项目，但需保留语义及相对路径清单。
6. 正常结束、失败、预算停止都写明最后有效时刻。只有所有必需检查真正完成且通过，阶段才可为 `PASS`；部分成功用 `completed_subchecks` 列出，不把全阶段涂绿。
7. 最终回复按“状态与通过范围—结果入口—最重要的三项数值—失败/缺项—实际修改—下一阶段合同”报告，附真实可打开路径。停止，不执行 Z1。

**可视化底线：** 至少有可离线打开的模型/网格视图、可读的定量验收图、数据与日志入口。适用的细胞或流体字段必须来自本次原始快照。可旋转、选对象、剖切、透明、时间同步和色标单位按共享合同验收；无动力学的阶段不伪造时间曲线。用于绘图的抽样不能影响数值验收，展示平滑不得改变求解几何。

**状态细分：** `NOT_RUN / RUNNING / PASS / FAIL_NUMERICAL / UNRESOLVED / BLOCKED_DEPENDENCY / BLOCKED_SPEC / BLOCKED_DATA / STOPPED_BUDGET`。另记录 `physics_status`、`visualization_status` 和 `claims_status`，避免“计算通过但交付缺失”或“数据不足但合成工作有效”被混淆。
